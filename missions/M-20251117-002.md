# Mission M-20251117-002 – Implement Mission Git Tooling

- **Mission ID:** `M-20251117-002`
- **Status:** `done`
- **Owner:** `codex`
- **Created:** 2025-11-17
- **Links:** `missions/M-20251117-001.md`
- **Worklog:** `worklogs/M-20251117-002/WORKLOG.md`

## Summary
Build the enforcement layer (scripts + hooks) that validates mission branches, worklogs, status alignment, and tests before code can be pushed or merged.

## Motivation
The governance doc (Mission M-20251117-001) defines policy; this mission encodes it mechanically to prevent human error, preserving the "safety, correctness, and traceability" canon and mission lifecycle guarantees.

## Dependencies
- `M-20251117-001` (Git governance spec)

## Deliverables
- [ ] `scripts/mission-verify.sh` (or similar) that checks:
      - Current branch matches `mission/<id>` and mission file exists.
      - Working tree clean except for intentional changes.
      - Required docs/worklog paths exist and reference the branch.
      - Tests defined in mission file have recorded results (hook can parse TODO markers for now).
- [ ] `.githooks/pre-commit` and `.githooks/pre-push` (or documented equivalents) that invoke the verify script and block on failure.
- [ ] Documentation inside `docs/22_GIT_GOVERNANCE.md` (or README snippet) describing how to install/use the hooks.

## Tests
- [ ] Run `scripts/mission-verify.sh --dry-run` on sample branches (success + intentional failure) and capture output in worklog.
- [ ] Demonstrate hooks preventing a push with missing worklog/dirty tree (record terminal output in worklog).

## Acceptance Criteria
- Hooks prevent committing/pushing from `main` and from mission branches failing verification.
- Script includes clear error messaging referencing mission files/worklogs.
- System owner can follow instructions to enable hooks locally and see them work.

## Rollback / Mitigation
Disable hooks by removing `.git/hooks` symlinks or toggling env var documented in the script; revert commit if tooling proves disruptive.

## Notes
Keep hooks POSIX-compliant where possible. Future CI integration will reuse the verify script, so design it to run non-interactively with exit codes.
